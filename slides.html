Slide 2 / 5 — Architecture

End-to-End Workflow

Admin

  • Create job (title, skills, level, location, open/closed)
  • Review applications
  • Update status: Applied → Shortlisted → Rejected
  • Dashboard: per-job counts, skill distribution, pipeline

Candidate

  • Create profile
  • Search & filter (skill / location / level)
  • ★ AI Matching — natural-language query
  • Apply (no duplicates, no closed jobs, profile required)

How AI matching works

Validate query → fetch open jobs → build GPT prompt → parse scores (0–100) + explanations → rank & return top 20. Fallback: keyword scoring if the API is unavailable — the feature never breaks in a demo.

Slide 3 / 5 — Workflow

Engineering Quality & Next Steps

What's solid

  • Proper HTTP codes (200/201/400/403/404/409/500) + field-level errors
  • Rules enforced: ownership, duplicates, closed jobs, one profile/candidate
  • 34 automated tests — Hypothesis property-based + integration
  • Resilient AI with graceful fallback

Honest limitations

  • JWT not production-hardened (dev secret)
  • SQLite for demo (ORM → Postgres is a config change)
  • No embedding cache on matching yet

What I'd do next

  • Vector embeddings for cheaper, better matching
  • Rate limiting + caching · refresh tokens · frontend tests
